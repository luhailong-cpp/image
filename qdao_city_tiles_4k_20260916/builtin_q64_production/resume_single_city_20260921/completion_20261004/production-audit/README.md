## 原生尺寸结论

历史管线固定 CORE=1024、HALO=115、1254² 原片、230 重叠，每个 4096 块用 4×4=16 次基础生成。提示词也大量硬写 1254。但有历史请求 4326² 实返 1254² 的明确记录，所以不能简单归因为提示词自己限小。

本轮实际验证了三次较大请求：c07 请求 4096²、c08 请求 4096²、c09 请求 2304²，实际均为 1254²，工具没有 size 参数。逐次证据列在 `verified-scope.json`。结论只覆盖**本轮入口的实际返回**，不把它写成 OpenAI 全局尺寸硬限制。

历史可解析原生记录中 756 份报告 1254²，另 1 份旧横幅为 1774×887（像素面积近似 1254²）；没有找到 2048²、2816² 的生成证据。实存名称含 native 的大尺寸图是 4326×230 邻块上下文裁片，不是大图单次原生输出。

## 可复用的更大输出方案

`larger-native-plan.json` 保存独立、未启用的 2×2 方案：每次真实返回 **2304²**，CORE=2048、HALO=128，相邻重叠256，四片构成4352²含上下文，裁掉四周128得4096²。必须先检查解码后的实际尺寸和记录；若仍返1254，立即停在该输出并保留失败证据，禁止放大适配。该方案可将基础生成从16次降为4次，但本轮2304试验失败，**现在不能当作已可执行的内置加速通道**。

即使另一个被授权入口能原生输出2880²或3840×2160，它们也不是4096²，仍需数张重叠生成并验缝；不能把“4K”营销名称当作4096方块。这里未调用 API/CLI，也没有更改全局配置。

## 工作量下界与实际瓶颈

按当前每块16原片管线，**1763×16 = 28,208 张基础原片**仍缺；如果那一张揽仙原片最终兼容，最乐观可降为28,207。此数未含区域引导图、拒稿、接缝修复、已有29块返工、四边与交点验收、日夜几何对齐和实机检查。不是时间估计，也不表示生成这么多张就自动通过。

每块16片还产生3横+3纵内部缝和9内部交点。旧做法在低清布局上强贴邻块 halo，容易把参考拼贴边复制成新材质边，再花多次生成修它。root 正在采用已知原生像素+透明缺失区的跨边 outpaint，并在已有结构正确时做有上限、保留外边的色差配准；这些方案需逐块验证，不能以重复小修数量代替完整4K/整城坐标覆盖增长。
