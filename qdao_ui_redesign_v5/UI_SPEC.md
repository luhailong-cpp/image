# 五行奇谈 · UI 与场景规范 v5

日期：2026-09-06。本文描述登录、选服、选角、主城 HUD、静态战斗背景、战斗入场与通用控件的交接规范；它不代表已经实现或通过客户端验收。中文文案与演示数据的唯一维护入口为 [copy.zh-CN.json](copy.zh-CN.json)，图片承担视觉参考作用。

## 1. 范围与数据约定

| 文件 | 负责内容 |
|---|---|
| `copy.zh-CN.json` | 中文文案、状态名、演示服务器与角色，以及演示选择项 |
| `UI_SPEC.md` | 层级、布局关系、交互和状态规则 |
| `source/*.prompt.txt` | AI 生成的登录、选服、选角、战斗背景及入场/云气指令；不适用于原生 SVG 主城 HUD |
| `manifest.json` | 实际来源图片、原生尺寸和标准导出记录 |
| `export_ui.py` | 从来源图制作标准尺寸导出的本地逻辑 |
| `components/` | 通用控件的矢量、透明导出、清单及独立重建说明 |
| `hud/` | 主城按钮的原生 SVG、透明皮肤/标签、排布记录和本地构建脚本 |

`demoData` 中的 ID 仅用于本演示内部引用，不是生产区服 ID 或角色 ID。服务器分组与推荐排序、账号身份、角色容量、职业体系、等级数值和宠物关系均未确认生产规则。三槽、八服及人物名称等演示数据可随业务确认替换。

`product.title` 为用户已确认的正式游戏名“五行奇谈”，`product.finalNameConfirmed` 为 `true`。`productionDataConfirmed` 仍为 `false`，仅表示服务器和角色等生产数据未确认。当前登录页不定义账号密码输入、鉴权协议或账号切换弹窗内容；“切换账号”“公告”“设置”保留明确入口，具体业务另行定义。

## 2. 统一视觉与控件层级

- 玉绿用于主要框架与功能面板，米白提供文字承载面，暖金突出当前选择和主要操作；太极、葫芦、云纹作为装饰体系。
- 场景沿用主城、仙山与云气的美术定调并制作新版画面。人物保持大头、圆脸、短躯干、玉绿袍与金色发带；登录和选角统一使用灵秀 Q 版九尾狐，狐吻、尖耳与九尾轮廓清楚。风格方向参考《问道》式的灵秀 Q 感，具体形象独立设计，避免团子猫感。
- 登录、选服、选角各保留一个最高层级的继续按钮；返回或切换为次一级，账号、公告、设置为辅助入口。主城 HUD 的三个功能入口按同一控件体系排列。装饰不遮盖标题、选中标记和点击区域。
- 原生文本位于装饰层之上。状态、姓名、等级、服名、按钮、搜索值和空状态均通过 JSON 或实际业务数据填充；语言变化不依赖重新生成整张背景。
- 主画面按 2560 × 1080 目标比例设计。来源原生尺寸和导出重采样由清单记录；其他屏幕比例需按客户端布局规则处理，不能假定拉伸整张图即可接入。

## 3. 页面 01：登录

| 区域 | 内容与职责 | 文案来源 |
|---|---|---|
| 标题 | 正式游戏名“五行奇谈”，建立独立入口页的识别 | `product.title` |
| 主视觉 | 主城环境、新版 Q 道童与九尾狐，保留前景控件空间 | 对应视觉稿 |
| 当前服务器 | 当前选中服名、状态图标与状态文字 | `demoData.selectedServerId` 对应服务器，`serverStatusLabels` |
| 主要入口 | 选择服务器；进入游戏 | `pages.login.actions` |
| 辅助入口 | 切换账号、公告、设置 | `pages.login.secondaryActions` |

演示流程中，“选择服务器”前往 02；“进入游戏”在当前区服可进入时前往 03 选角。真实客户端应在自己的鉴权与区服可用性检查之后继续，本文不定义登录成功条件。

当前区服处于维护状态时，“进入游戏”进入 disabled 状态，显示 `messages.serverMaintenance`。区服名称和状态仍可读；“选择服务器”保持可用，使玩家能够改选。繁忙状态只是提示，是否排队由后续业务决定，演示不自动把繁忙区服禁用。

## 4. 页面 02：选择服务器

| 区域 | 内容与职责 |
|---|---|
| 页标题 | `pages.serverSelect.title` |
| 分类入口 | `pages.serverSelect.categories` 中四个分类，顺序保持 JSON 定义 |
| 搜索 | 使用 `pages.serverSelect.searchPlaceholder`；当前输入作为原生文本展示 |
| 区服列表 | 2 列 × 4 行演示卡片，按 `demoData.servers` 顺序排列；清单含八个区服 |
| 当前选择摘要 | `pages.serverSelect.selectionTemplate`，通过 `{serverName}` 填入选中服名 |
| 底部操作 | 返回；进入选角 |

演示初始选择由 `demoData.selectedServerId` 指定。每张卡片至少显示服名、状态图标与文字；推荐服附独立“推荐”徽记，选中服附勾选形状及“已选择”文字。分类的真实成员关系、最近登录记录和推荐策略由业务提供，本稿不推断八个演示服务器的生产分组。

选择可进入的区服时更新卡片 selected 状态和底部摘要；任一时刻最多有一个当前选择。点击“进入选角”前再次检查区服可用性，符合条件后进入 03；“返回”回到 01，并保留演示选择。

维护卡片使用 disabled 状态，显示维护图标、状态文案及禁入原因，不能成为可进入的目标。若已选服务器随后转为维护，保留选择摘要用于告知变化，禁用继续操作并提示改选。不能仅靠灰度或绿色/红色差异表达是否可进入。

### 搜索无结果

输入框保留查询值；卡片区域显示 `messages.noServerResults`，并提供 `pages.serverSelect.clearSearch`。无结果时禁用“进入选角”，即使此前存在选中 ID，也不能从不可见旧选择继续。清空查询后恢复列表，重新显示当前有效选择，再根据状态决定是否启用继续。

搜索匹配、拼音、区号和别名规则尚未确认；演示实现可先做服名文本匹配，并清楚标注该范围。无结果是空状态，不是网络故障提示。

## 5. 页面 03：选择角色

| 区域 | 内容与职责 | 数据来源 |
|---|---|---|
| 标题与当前服 | 选择角色、当前服名 | `pages.characterSelect.title` 与选中服务器 |
| 左侧槽位 | 两个已有角色、一个创建空位 | `demoData.characterSlots` |
| 中央主视觉 | 选中 Q 道童与同行九尾狐 | 选中角色和对应视觉素材 |
| 右侧信息 | 名称、职业、等级、所属区服、同行灵宠 | `pages.characterSelect.fields` 与选中角色数据 |
| 底部操作 | 返回选服、进入仙境 | `pages.characterSelect.actions` |

登录宠物由 `demoData.loginCompanionId` 引用，初始选中角色的 `companionId` 引用同一只九尾狐，右侧同行灵宠显示“九尾狐”。初始选中角色由 `demoData.selectedCharacterId` 指定。第一个槽位展示选中道童的姓名、28 级和职业；第二个展示未选的清铃、16 级与女性小头像。清铃的职业、详细形象及同行宠物未指定，JSON 使用 `null`，接入时省略未知字段，不补写推测内容。

点击已有角色槽更新唯一 selected 状态、中央展示和右侧信息。当前视觉稿完整呈现初始道童状态；另一角色的完整选中主视觉需要后续素材任务补齐，不把初始道童图当作清铃的形象。

空槽采用加号形状与“创建角色”文字，点击只进入待实现的创建角色流程入口；空槽不是可进入世界的角色。若当前焦点或选择位于空槽，禁用“进入仙境”，显示 `messages.chooseExistingCharacter`，同时保持创建入口可用。

“返回选服”回到 02；“进入仙境”只有在选中已有角色且区服可进入时可用。角色归属需与当前服匹配，区服切换后由业务刷新角色列表。本稿仅演示当前服的角色，不定义跨服角色或创建角色的持久化行为。

## 8. 状态规范


状态 ID 使用稳定英文键；用户可见文字从 JSON 读取。下面定义交互要求；通用控件已有的状态资源、九宫格与文字边距以 [组件说明](components/README.md) 和 [组件清单](components/manifest.json) 为准，状态图片本身不实现事件。

| 状态 | 视觉与文字 | 操作规则 |
|---|---|---|
| `normal` | 清晰边界和完整标签，未显示选中勾记；保留足够辨识度 | 满足条件时可点击 |
| `selected` | 强化描边或选中框，同时显示勾记与“已选择”；分类页签也需要形状/文字辅助 | 保持唯一选择，重复点击不产生第二个选择 |
| `disabled` | 降低强调程度，同时展示禁用原因或状态图标；文字仍可辨认 | 不执行继续、选择或进入动作；适用的改选、返回、清空等恢复操作保持可用 |

服务器 selected 不等于推荐；两种状态使用不同标记。维护是服务器业务状态，会使进入操作 disabled。空槽是创建入口，不是维护状态。键盘焦点和指针悬停也不能冒充 selected；原生控件应提供可辨认的焦点边界，并采用与视觉顺序一致的导航顺序。

## 9. 接入时的完成标准

剩余任务与新窗口的执行顺序由 [后续交接文档](../docs/WUXING_QITAN_HANDOFF.md) 统一维护。以下项目供后续客户端任务验证，本次视觉稿不宣称已经完成：

- 各页面显示文案与 `copy.zh-CN.json` 一致，正式名称使用“五行奇谈”；动态文本和演示数据有独立数据入口。
- 登录与选角展示同一形象方向的灵秀 Q 版九尾狐，同行灵宠文案与图像一致。
- 主城保留“战斗”“观战”“角色”三个入口语义；森林石桥交付按静态战斗背景使用。
- 登录、选服、选角之间的继续与返回符合上述演示流程；未定义业务以明确入口保留。
- normal、selected、disabled 可辨认，区服推荐与选中能够区分，状态提示不只依赖颜色。
- 维护区服无法进入；区服状态变化后重新校验；搜索无结果不能误用隐藏的旧选择继续。
- 空槽进入创建入口而非游戏；缺少已选角色时不能进入仙境；切换已有角色会同步主视觉和信息。
- 原生文本没有与视觉稿烘焙文字叠加；实际分辨率、触控/键盘操作和资源拆分由客户端检验。

游戏名已经确认。后续实现前仍需确认账号体系、服务端区服状态、分类/搜索规则、角色槽数、创建流程及主城按钮对应的业务。未确认项保留演示范围，不据此声明 Unity/FairyGUI 接入或生产业务可用。
