# 四职业技能

正式目录为 `Assets/Resources/Skills/catalog.json`，技能图为 `Assets/Resources/UI/Skills/<id>.png`。32 个技能：破军 1101–1108、玄霄 1201–1208、丹心 1301–1308、逐风 1401–1408，每职业 5 主动、3 被动；名称独立于功能参考截图。

角色窗口侧栏“技能”进入技能簿，展示本职业技能、等级、当前学习条件、法力百分比、冷却回合、目标及说明。图标使用独立 Sprite，所有等级、金币、状态和操作文字由原生 TMP 控件绘制。主体复用已确认 `AttributesPaintedV2` 纸面与玉绿暖金皮肤。

## 权威状态

`SkillClient` 通过既有 `IBattleTransport` 与 `GameClient` RPC 管线请求 `ListSkills`，只按服务器 `catalog` 返回可见职业技能。静态 JSON 只提供战斗表现与离线资源映射，不能授予技能。

`UpgradeSkill` 同时承接学习（等级 0→1）与升级。客户端提交技能 ID、期望当前等级、次数 1 或 10；服务器检查职业、解锁级别、等级上限、金币及战斗状态。客户端不提前改等级或余额，一次只允许一个在途请求。批量操作可以部分完成，UI 明确显示实际升级次数与停止原因。失败若带权威 `state`，也完整替换本地快照。断线后清空快照并丢弃旧会话的迟到响应。

本版无降级协议，因此没有可产生虚假效果的降级按钮。被动自动生效，不能作为战斗指令提交。

## 战斗

战斗技能选择器使用服务器 `SkillTableIds`，隐藏被动；显示独立图标、中文名、实际法力消耗和当前冷却。耗蓝按目录比例乘最大法力向上取整。敌方技能只能选择存活敌人，治疗/增益只能选择存活友方，自身技能默认选中施法者后等待确认。服务器仍负责最终目标合法性校验、群体补齐、扣蓝及结算。

技能演出映射位于 `Assets/Resources/Battle/skill_presentation.json`；使用现有斩击、突刺、雷、冰、治疗与增益特效。新的技能图标不是新的完整战斗动画。

战斗回放优先读取 `BattleEventItem.mana_delta` 的明确正负值，同次行动多条法力变化累计净值；玄霄“太虚澄心”自身回蓝不再误判为耗蓝。蓝条仍直接使用服务器的 `target_mana_after`，旧协议未带有符号字段时保持耗蓝兼容。

## 验证

运行时编译：`pwsh -File tools/client_compile_check.ps1`。

EditMode 测试：`MmorpgClient.Tests.EditMode.Battle.SkillClientTests`，覆盖技能归属、期望等级、防重复请求、部分批量升级、失败快照、断线迟到响应、初次学习、余额限制、网络超时、敌友/自身/死亡目标与耗蓝取整。

`SkillManaReplayTests` 覆盖自身回蓝、同次行动先消耗再回复、敌方法力减少、明确零变化及旧协议兼容；`SkillResourceTests` 验证32张Sprite、独立名称及主动演出映射。

当前已有 Unity 编辑器占用项目时，不应再启动该项目的第二个 batchmode 实例。独立核心测试可以验证网络状态及规则；实际窗口视觉和在线流程须在 Unity 与真实服务器中验收。
