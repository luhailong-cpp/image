## 交付结构

- `source/<编号-名称>-E.png`、`-W.png`：分别生成的原生方向图。`E` 为敌方左上朝向右下，`W` 为我方右下朝向左上。来源图不进行放大覆盖。
- `runtime/<编号-名称>/idle_E.png`、`idle_W.png`：1024×1024 RGBA，透明背景，同宠两向采用共同缩小因子和脚点，pivot 为 `(0.5, 0.08)`，以左下为原点。
- `ui/<编号-名称>/fullbody_1024.png`：同源透明全身图。
- `ui/<编号-名称>/portrait_512.png`：人工核对头像区域后裁切的 512×512 透明画布；不把全身缩图当头像，裁切区域不足 512 时保留原生细节并居中留白，不上采样。
- `prompts/`、`records/`：真实提示词、调用记录、批次设置快照、来源元数据和处理诊断。
- 原图旁 `*.generation.json` 记录对应图的生成证据；导出旁 `*.derived.json` 记录原图哈希与来源链。完整原生 PNG 同时按哈希归档至 `source/native-archive/`，以保留替换前的证据。

以上是**静态双朝向**，不含待机、行走、攻击、施法、受击或死亡动画。当前未修改客户端代码、数据表、资源引用或 Unity 导入配置，也未完成引擎接入验收。

## 高清与模型记录

原生来源的短边必须至少 1024 像素；输出为 1024 不代表原图原生 4K。此包不制造 4096 放大图来替代原生细节。

本批次按用户要求，以可用 GPT Image 2.5 和最高视觉完成度为目标，不能用时采用 GPT Image 2.0。内置工具未开放型号与质量选择器，因此实际提交的 `model`、`quality` 为 `null`；没有可核实返回值的实际模型与质量也为 `null`。配置目标、实际提交参数、工具返回和嵌入的软件版本分别保存，不能相互替代。C2PA 检查只读取元数据及 PNG CRC，不验证签名。

原图到记录的索引位于 `manifest.json` 每项 `directions.E/W.generationRecord`；导出到原图的链路位于 `outputs.*.record`。

## 重建与诊断

使用本机 Python 3、Pillow 与 NumPy：

```powershell
python designs/pets-20260924/build_pack.py --diagnose-only --only 03-xuehu
python designs/pets-20260924/build_pack.py
python designs/pets-20260924/build_overviews.py
python designs/pets-20260924/validate_pack.py --require-complete
```

[asset-config.json](asset-config.json) 保存源图坐标中的脚点、身体范围及头像裁切参数。头像必须设置人工核对的 `portrait.crop` 与 `portrait.reviewed=true` 后才导出。缺少任何一向时保留诊断和来源记录，等待同宠两向齐全后计算共同缩放，不先做互不一致的单向正式输出。

处理器优先保留真实 Alpha；只有不透明且边缘可靠呈纯洋红时，才清除连接到画布边界的洋红区域，避免全局删除粉衣、粉尾、红穗等本色。已授权的透明清理仅处理不可辨认的微小孤立点（可见面积不超过16像素、长宽不超过8像素），并记录每块范围；另外清除远离alpha≥2轮廓外扩8像素范围的alpha=1/255底噪，保留近轮廓抗锯齿。高饱和本色不作全局删除，原生图保持不变。源图触边、宽翼导致身体过小、脚点与头像取景均需逐张实看。

构建是确定性的：输入和设置相同时输出一致，不重写字节未变的文件；新来源不会回填旧图模型版本，也不会改动生成者保存的提示词或 receipt。
